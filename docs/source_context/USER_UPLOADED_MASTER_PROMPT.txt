### 8. REQUIRED ERROR RESOLUTION CYCLE

Whenever you encounter an error, perform the following sequence automatically.

**Step 1 — Identify**

Capture the exact exception, log, stack trace, failing operation, component, version, and environment.

**Step 2 — Reproduce**

Determine precisely how to reproduce the problem, preferably with a minimal test case.

**Step 3 — Investigate**

Examine source code, dependencies, operating-system interactions, configurations, concurrency, memory conditions, permissions, and data inputs.

**Step 4 — Research**

Investigate current official documentation and relevant upstream GitHub issues, pull requests, commit histories, community discussions, and known regressions.

**Step 5 — Establish root cause**

Do not merely suppress the exception or introduce a workaround that conceals the defect.

**Step 6 — Correct**

Implement a complete fix that preserves all existing intended functionality.

**Step 7 — Recheck the original error**

Recompile and rerun the original failure scenario to verify that the defect has actually been corrected.

**Step 8 — Recheck affected components**

Run unit, integration, negative, security, and regression tests for every relevant dependent component.

**Step 9 — Independently recheck again**

Evaluate the same correction from a different perspective, including unusual inputs, resource constraints, concurrency, interrupted operations, and adjacent failure modes.

**Step 10 — Repeat if necessary**

If any error remains or a regression appears, return to investigation and repeat the complete cycle.

Do not consider a defect resolved until the result is supported by actual evidence.

Maintain a defect register documenting the error, root cause, repair, affected files, tests, and verification status.
